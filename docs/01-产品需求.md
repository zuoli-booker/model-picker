# 大模型性能排名网站 + 大模型路由应用 · 原始产品需求

> 整理日期：2026-09-28
> 说明：本文档忠实整理左力提出的原始产品设想与补充约束，作为需求底稿。不含评估结论与方案调整建议（相关内容见《大模型排名与路由应用-可行性评估报告.html》与《大模型排名与路由应用-调整方案.md》）。

---

## 一、需求背景

大模型数量爆发、能力各异，用户在选型时缺乏一站式了解各模型性能的渠道；同时，用户手头往往有多个可调用的大模型（各自有 API Key），但缺少工具帮助其根据任务需求在多个模型间做合理的调度分配。

因此构想两个配套产品：**大模型性能排名网站**（解决"了解模型"）与**大模型路由应用**（解决"用好模型"）。

---

## 二、产品一：大模型性能排名网站

### 2.1 定位

基于目前最主流的大模型性能排名，对当前已发布的大模型各项性能进行排名展示。

### 2.2 功能

- 聚合各主流榜单的最新排名数据
- 对当前已发布的大模型按各项性能维度进行排名
- 用户可以在网站上了解想了解的模型的性能排名情况

### 2.3 关键约束

- **只做聚合，不做评测**：网站只提供最新的各主流榜单排名，不自己去做模型测试的事情

---

## 三、产品二：大模型路由应用

### 3.1 定位

用户基于对大模型各维度性能的了解，结合自己手头可以调用的大模型，按实际工作需要，从任务完成的速度、质量、成本等维度出发，配置生成路由策略；并将策略应用到可下载的路由应用中，供自己的智能体等应用通过 API 调用。

### 3.2 用户流程

1. **了解模型**：在排名网站上了解各模型各维度性能
2. **登记模型**：在路由应用中接入自己的 API Key、URL、模型名称
3. **配置策略**：基于自己的实际工作需要，按速度 / 质量 / 成本等维度的考虑，在网站上配置生成路由策略
4. **下载应用**：在网站上下载路由应用，将路由策略配置到路由应用中
5. **接入调用**：让自己的智能体等应用，通过 API 的方式连接路由应用，按照路由策略调用大模型

### 3.3 关键约束

- **BYOK 模式**：用户接入自己的 API Key、URL、模型名称，平台不进行模型托管
- **法律切割**：模型 API 均为用户自己提供，与网站和路由应用没有法律上的关系

---

## 四、需求核心（用户自述）

整个需求的核心是两点：

1. **提供一个网站，能了解各模型的各项性能**
2. **能根据用户自己能调用的模型情况，生成路由策略**

---

## 五、需求边界速览

| 维度 | 做 | 不做 |
|---|---|---|
| 数据来源 | 聚合各主流榜单最新排名 | 自建模型评测/测试 |
| 模型供给 | 用户自带 API Key / URL / 模型名（BYOK） | 平台托管模型、代售 API |
| 策略生成 | 按用户可调用的模型 + 速度/质量/成本维度配置 | （未限定实现方式） |
| 交付方式 | 网站 + 可下载路由应用，API 方式接入 | — |
| 法律责任 | 工具与信息平台定位 | 与用户 API 调用无法律关系 |

## 六、待明确事项（原始需求未覆盖，供后续补充）

- 目标用户群体与优先级（个人开发者 / 团队 / 企业）
- 排名网站覆盖的榜单清单与更新频率要求
- 路由策略的配置粒度（按任务类型？按请求特征？）
- 路由应用的形态（Docker / 二进制 / 云服务）
- 是否做用户体系、策略云端保存
- 商业化意向（免费 / 开源 / 收费）
