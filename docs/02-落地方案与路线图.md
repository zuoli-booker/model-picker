# 轻开发者 AI 工具站——终版落地方案与路线图

> 版本：v1.0（合成版）｜日期：2026-09-28
> 合成来源：方案A（阿腾·开源验证优先）+ 方案B（社区平台的 L2/L3 交付机制）+ 方案C（选型顾问站的内容切入骨架）+ 人群定位讨论（轻开发者）+ 平台与性别结构核查

---

## 0. 执行摘要

**一句话定位**：面向"轻开发者"（用过 WorkBuddy/Trae、嫌套餐贵、想按自己的想法调 API 的非程序员上班族），以内容运营聚人、以开源策略生成器立身、以可下载的 BYOK 路由应用承接，做"接哪个模型 + 帮我配好"这件事。

**核心逻辑（三层飞轮）**：

```
内容层（小红书+B站，获客）  →  工具层（策略生成器→路由应用，转化）  →  私域层（微信群/星球，留存）
        ↑                                                                    |
        └────────────── 模型换代提醒 / 用户案例反哺选题 ←──────────────────────┘
```

**与其他方案的关系**：
- 采纳方案C的骨架：内容先行切入、止损纪律、"顾问站"而非"基础设施"定位
- 采纳方案B的交付机制：L2 复制粘贴 + L3 智能体部署指令的分层交付（其 42-84 万成本、托管版、社区冷启动三处硬伤不采纳）
- 采纳方案A的核心：策略生成器开源化、排名站降级为副产品、BYOK 自托管、第一年明确放弃清单

**关键约束**：单人副业，业余时间每天约 1 小时。所有设计围绕一条原则——**用最小维护成本，最先验证最大的不确定性**。

## 1. 目标人群（定位基准）

### 1.1 人群画像：「轻开发者」

| 维度 | 描述 |
|---|---|
| 身份 | 普通上班族（运营/设计/产品/行政/市场等非技术岗为主） |
| AI 经验 | 用过 WorkBuddy、Trae、豆包、Kimi 等应用级工具，不是纯小白 |
| 核心痛点 | ①套餐贵或额度不够用；②应用的能力边界卡住自己的想法，想按自己的需求调用大模型 API |
| 能力边界 | 代码不强，但爱学习、爱尝鲜、能照着教程操作终端和复制配置 |
| 心理诉求 | 省钱 + 掌控感 + "我也能折腾 AI"的成就感 |
| 性别结构 | 估算男性 60-70%（介于 AI 工具大众用户均衡分布与 B站技术人群男 70-88% 之间） |

### 1.2 定位原则（已论证的决策）

- **人群做定位，场景做选题库**：AI 应用早期、垂直场景未定型，不锁死细分场景；每篇内容从具体场景切入（周报/文案/Excel/小红书运营），用人群共性痛点（省钱、动手、掌控感）串联。
- **服务"想用"的人，不是"想学"的人**：内容奉行"三分钟上手、直接给配置、复制粘贴就能用"，区别于知乎/CSDN 的"三段原理+十行代码+评论区争论实现是否优雅"。

## 2. 产品架构：一个核心资产 + 四层交付

### 2.1 架构总览

```
┌─────────────────────────────────────────────────────┐
│  L0 数据层（副产品）：主流榜单聚合管道                │
│     只聚合不自测：LMArena / Artificial Analysis /    │
│     OpenRouter Rankings / OpenCompass，2-3 个 API    │
├─────────────────────────────────────────────────────┤
│  L1 核心资产：模型策略生成器（开源）                  │
│     输入：我手头的模型清单 + 任务类型 + 速度/质量/    │
│     成本偏好 → 输出：推荐策略 + 解释 + LiteLLM 配置  │
├─────────────────────────────────────────────────────┤
│  L2 轻交付：复制粘贴配置（内容中直接带走）            │
├─────────────────────────────────────────────────────┤
│  L3 进阶交付：智能体部署指令（AGENTS.md / 复制这段话  │
│     给你的 AI 助手替你执行）                          │
├─────────────────────────────────────────────────────┤
│  L4 重交付：可下载路由应用（Docker 包，BYOK）         │
│     底座 LiteLLM（MIT），用户自带 Key/URL/模型名，    │
│     请求不经平台服务器，法律关系完全切割              │
└─────────────────────────────────────────────────────┘
```

### 2.2 各层职责与阶段

| 层 | 是什么 | 上线阶段 | 定位 |
|---|---|---|---|
| L0 | 榜单数据聚合脚本 + 自动生成的模型详情页 | 阶段2（为 L1 供数据） | 副产品，不做看板级打磨 |
| L1 | 命令行/Web 策略生成器，GitHub 开源 | **阶段0（第一个交付物）** | 核心资产与差异化壁垒 |
| L2 | 每篇内容附带可复制的配置块/提示词 | 阶段0 起持续 | 内容钩子，"每篇有可带走的东西" |
| L3 | 一段可粘贴给 WorkBuddy/Trae 等 AI 助手的部署指令 | 阶段1 | 承接"抄作业"刚需，私域活跃核心 |
| L4 | Docker 一键部署的 BYOK 路由应用 | 阶段2 | 留存基本盘，智能体可 API 接入 |

### 2.3 策略生成器的差异化设计

- **规则式，不做学习式**：策略 = 公开榜单数据 + 用户偏好加权，每条推荐附带"为什么"（可解释性即卖点）。学习式路由赛道已验证降温（Martian 转型、RouteLLM 停更、TensorZero 归档），不碰。
- **任务类型 → 榜单维度映射表**：如"写小红书文案 → 创意写作维度 + 中文语料权重"、"代码 → 编程维度 + 速度"。这是认知壁垒，不靠钱堆。
- **模型换代提醒**（阶段3 留存钩子）：榜单数据发现比用户当前策略更强/更便宜的新模型时推送"你的策略该更新了"——复用 L0 数据管道，边际成本极低，把低频选型决策变成订阅式顾问服务。

### 2.4 法律与合规边界（BYOK 专项）

- Key 只进用户自己部署的容器，请求不经过平台服务器 → API 转售、生成式 AI 备案、数据出境三类风险均不适用
- 平台性质是"工具软件 + 信息聚合"，不是 API 中转站
- 剩余合规四要点：①榜单引用标注来源；②底座只用 MIT/Apache-2.0（LiteLLM ✅，**避开 New API 的 AGPL**）；③页面挂免责声明；④推荐错误属服务质量问题而非法律问题

## 3. 内容与平台运营策略

### 3.1 平台组合

| 平台 | 角色 | 打法 | 依据 |
|---|---|---|---|
| **小红书** | 主阵地：获客 + 搜索长尾 | 图文笔记，教程+成本账+横评 | 25-40 岁学习型上班族浓度最高；强搜索吃"XX模型怎么用/多少钱"长尾；日均搜索 8 亿次；**本行方法论零学习成本**；平台正战略转型"AI 时代 App Store"（16 万开发者 +220%） |
| **B站** | 并行试水：深度信任 + 男性触达 | 图文转录屏视频（不出镜，成本可控），每 2-3 周一条 | 科技用户 2 亿、男性占 70%、AI 兴趣人群 8000 万、AI 内容播放年增 80%；与小红书（女 72%）形成性别互补 |
| **微信群/知识星球** | 私域：聚人 + 留存 + 转化 | 作业互抄、踩坑互助、新模型首发讨论 | 该人群"抄作业"刚需极强，社群粘性远高于内容关注 |
| **GitHub / V2EX / 掘金** | 工具冷启动 | 策略生成器开源发布，发一次即可 | 开发者社区传播效率高；不做人群运营 |
| 微信公众号 | 沉淀存档 | 深度横评/月报长文 | 打开率走低，不做主战场 |
| 抖音/快手 | — | **不做** | 人群错配，制作成本高 |

### 3.2 内容四支柱（每条终点都是产品）

| 支柱 | 选题示例 | 衔接 |
|---|---|---|
| ① 省钱成本账 | 《ChatGPT Plus 一年 1500，自己调 API 只要 80：手把手算给你看》 | 省钱的下一步是"多模型怎么配" → L1 |
| ② 动手教程 | 《15 分钟零代码调通第一个 API（非程序员版）》 | 教程终点是配置 → L2 |
| ③ 工作流模板 | 《我的多模型流水线：贵的干难题，便宜的跑量》 | 流水线=路由策略具象化 → L4 |
| ④ 模型横评 | 《DeepSeek V4 vs 豆包：该不该换？》 | 横评的结论是推荐 → L1 |

### 3.3 内容风格铁律

1. **零代码默认值**：所有教程假设读者不会写代码，只会复制粘贴和点鼠标
2. **每篇有可带走的东西**：配置块/提示词/清单，配合收藏动作
3. **成本透明**：每个方案标价，建立"这人不说虚的"信任
4. **语感性别通吃**：封面/标题用"3C 测评风"（终端截图 + 数据图表 + 大数字标题），不用精致生活方式风；人设为"爱折腾工具的运营人"（职场身份天然中性）

### 3.4 北极星指标

- **收藏率 > 8%**（该人群收藏远多于点赞，收藏=想照着做的意图信号）
- 辅助指标：评论中"求教程/求配置"的出现频率、私域进群率、L2 配置块被复制的反馈

## 4. 落地路线图

### 总览

```
阶段0（第1-2周）      阶段1（第3-8周）        阶段2（第9-16周）       阶段3（第5-12月）
开源验证+账号基建  →   内容冷启动+私域搭建  →   产品化闭环          →   飞轮与留存
   [门1:工具验证]        [门2:内容验证]           [门3:转化验证]          [持续运营]
```

### 阶段0：开源验证 + 账号基建（第 1-2 周，每周约 7 小时）

**目标**：用最小成本回答"策略生成器有没有人要"，同时完成运营基建。

| 任务 | 产出 |
|---|---|
| 策略生成器 MVP（命令行版） | 输入模型清单+任务+偏好 → 输出推荐策略+解释+LiteLLM 配置；GitHub 开源（MIT） |
| 数据源接入（精简版） | 手动整理 20-30 个主流模型的榜单/价格数据（JSON 文件即可，先不建爬取管道） |
| 首批 L2 交付物 | 3-5 个可直接复制的配置模板 |
| 运营账号基建 | 小红书专业号 + B站账号注册；首批 30 篇选题规划（复用 48 家医院矩阵的批量选题方法论） |
| 首发渠道 | GitHub README + V2EX/掘金各发一帖；小红书发 2-3 篇预热 |

**🚪 门1（第 2 周末）**：GitHub 获得 ≥30 star 或有用户 issue 反馈 / 小红书笔记有自然收藏 → 进入阶段1。两周无任何水花 → **止损：停项目或换切入角度**（沉没成本仅 2 周）。

### 阶段1：内容冷启动 + 私域搭建（第 3-8 周，每周约 7 小时）

**目标**：验证内容定位与人群匹配，开始聚人。

| 任务 | 节奏 |
|---|---|
| 小红书发文 | 8-12 篇（每周 2 篇），四支柱轮换，语感按 3.3 铁律执行 |
| B站并行试水 | 2-3 条录屏视频（小红书图文转制，不出镜） |
| L3 智能体部署指令上线 | 《复制这段话给你的 AI 助手，替你把路由配好》——内容→工具的关键衔接件 |
| 私域搭建 | 微信群起步（免费）；50 人后再评估知识星球 |
| 评论区运营 | 每条"求教程"评论都是下篇选题；24h 内回复 |

**🚪 门2（第 8 周末）**：
- 内容验证线：小红书笔记收藏率 >8%，且评论区出现"求教程/求配置"类互动 → 通过
- 性别验证闸门：小红书后台男性粉丝占比 ≥20%（<20% = 语感跑偏，按"3C 测评风"修正后再观察一轮；≥30% = 触达正常）
- B站去留：录屏视频数据若与小红书同选题表现相当 → 加码；明显跑不动 → 降频保留
- **两轮（各 4 周）均无水花 → 止损：停内容运营**，工具转为纯开源维护模式

### 阶段2：产品化闭环（第 9-16 周，每周约 7 小时）

**目标**：把验证过的需求做成完整产品闭环（进入开发重投入期）。

| 任务 | 说明 |
|---|---|
| L0 榜单聚合管道 | 定时拉取 2-3 个官方 API（OpenRouter Rankings + Artificial Analysis + OpenCompass），自动生成模型详情页（SEO 副产品）；新增模型自动进入 L1 数据 |
| L1 Web 版策略配置器 | 网页表单：我的模型清单 + 任务 + 偏好滑杆 → 可视化策略 + 解释 + 配置文件下载 |
| L4 可下载路由应用 | LiteLLM 底座 + 策略导入，打 Docker 包，一键部署文档（面向非程序员的保姆级） |
| 换代提醒 v1 | 基于榜单数据对比用户策略，产出"该更新了"周报内容（暂用内容/社群推送，不做站内系统） |
| 私域承接 | 配置器链接进社群；群内案例反哺内容选题 |

**🚪 门3（第 16 周末）**：配置器月使用 ≥300 次 / Docker 包下载 ≥100 次 / 私域用户向工具的自然转化率 ≥10% ——三项达到两项即通过，进入阶段3。未通过 → 冻结产品迭代，转入纯内容+社群维护模式（此时已有内容资产和社群，不算失败退出）。

### 阶段3：飞轮与留存（第 5-12 个月）

**目标**：让"来过的人"持续回来，探索轻商业化。

| 方向 | 动作 |
|---|---|
| 榜单站完善 | 模型详情页 SEO 慢养（此时已有真实流量数据指导投入） |
| 策略版本管理 | 用户保存策略历史，换代提醒触发更新 |
| 用量/成本看板 | 路由应用内置统计，高频查看入口 |
| 商业化试探（谨慎） | 知识星球付费版（深度教程+策略托管文档）/ 内容付费合集；**不做托管 API、不做企业版销售**（第一年纪律） |

### 明确不做清单（第一年，防范围蔓延）

- ❌ 学习式/语义路由（赛道已降温）
- ❌ 模型托管、API 中转（与 BYOK 定位矛盾，且有合规风险）
- ❌ 用户体系、账号系统（工具够用即可）
- ❌ 云端策略同步（本地文件导入导出够用）
- ❌ 企业版、销售团队、融资
- ❌ 抖音/快手运营
- **决策闸**：每个新功能先问一句——"它每月增加多少小时维护时间？"超过 2 小时/月的，默认不做。

## 8. 里程碑总览（一页纸）
