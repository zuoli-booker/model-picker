## 一、Jev 与 Laya 是什么

两者同属 2026 年 9 月爆火的新品类：**"System 1" 非自回归决策模型**——不做文本生成，输入一段文本（state）+ 一组预定义的类型化问题（choice 选择题 / score 打分 / noul 是非概率），一次前向传播直接输出每题的概率分布和置信度。**零输出 token、毫秒级延迟、不会幻觉**。

| | **Jev** | **Laya** |
|---|---|---|
| 出品 | TypeSafe AI（前 OpenAI 研究员 Diogo Almeida，$40M 种子轮，DCVC 领投） | Nandakishor M / Convai Innovations（印度独立开发者） |
| 发布时间 | 2026-09-15 | 2026-09-18（Jev 发布后 3 天） |
| 形态 | 闭源托管 API（typesafe.ai，亦上 OpenRouter/Vercel/Cloudflare） | **开源：Apache-2.0，代码+权重全开放** |
| 参数量 | 未公开 | 421M（英文 ModernBERT）/ 322M（多语言 mmBERT，100+ 语言含中文） |
| 价格 | $0.042/MTok 输入，输出免费 | 免费（自托管，CPU 可跑） |
| 速度 | ~236-523ms（含网络） | T4 GPU 33ms / CPU 200-460ms / 批处理 7.2ms |
| 选项上限 | Choice 最多 255 项 | 约 20 项后准确率明显下降 |
| 生态热度 | 内测 36 小时清 14 万人 waitlist | **9 天 2.3万-2.7万★**，Hugging Face 趋势第一，HF CEO 亲自背书 |
| 关键短板 | 厂商自测数据为主，不可自托管，数据出境 | **零样本接近随机**（typed-decisions 基准 0.36 vs 随机 0.318），需微调才可用；多选项场景大幅落后 Jev；置信度校准偏高 |

**一句话**：Jev 是"托管版决策模型"，Laya 是"开源版决策模型"。品类本身已被验证（9 天 2.7 万★说明痛点真实：LLM-as-a-judge / 路由决策太贵太慢），但 Laya 开箱即用性被作者自己标注为"Honest limits"——**必须微调**。

## 二、对 router 项目的价值：你的直觉是对的，但有明确的适用边界

### 2.1 我们的路由决策现状

当前 MVP 的决策链：**用户在 CLI 里人工选任务类型** → 规则引擎按任务-维度权重表选模型。决策是"静态、人工触发"的。

### 2.2 决策模型能补哪一环

路由应用（L4，Docker BYOK）上线后，真实场景是：**用户的智能体发进来一段请求，没人替它选任务类型**。这是规则式路由做不到的——除非让用户写规则，那就回到 Martian 失败的老路。决策模型恰好补这个洞：

```
智能体请求 → [Laya 本地 sidecar] 任务分类（choice：6种任务类型）+ 质量敏感度（noul）
           → 置信度 ≥ 阈值：自动路由到策略对应模型
           → 置信度 < 阈值：回退规则引擎 / 按首选模型执行
           全程 30-460ms、零 API 费用、数据不出本机
```

这正好同时满足我们三条硬约束：**不重复造轮子**（直接调 Laya，Apache-2.0）、**BYOK 数据不出境**（Laya 跑在用户自己容器里，Jev 托管版反而不符合这条）、**可解释**（输出的是概率分布，可记录每次决策的理由）。

### 2.3 但必须泼两盆冷水

1. **Laya 零样本不可用**（作者自己承认）。任务分类要可用，需要在标注数据上微调（官方提供 Kaggle 免费 GPU 4-5 小时的微调 notebook）。这意味着我们要维护：标注数据集 + 微调管道 + 阈值校准——**这是一条持续的维护线**，不是一次性集成。
2. **选项多了就不行**（>20 选项准确率骤降）。我们的场景是"6 种任务类型"（choice 选项少 ✅）和"从用户 3-8 个模型里选一个"（选项少 ✅）——场景恰好落在 Laya 的舒适区，这是好消息。

### 2.4 结论与建议（待确认）

| 项 | 建议 |
|---|---|
| 时机 | **不进入 MVP / 阶段1**。列为阶段3（产品化闭环之后）的"智能决策模式"增强项 |
| 选型 | 只用 **Laya**（Apache-2.0 + 本地跑，符合 BYOK；Jev 托管版数据出境，违背项目立身之本，仅作对标参考） |
| 形态 | 路由应用内嵌 **Laya sidecar 容器**（laya-serve 已提供 Jev 兼容的 HTTP 接口），默认关闭，配置里一键开启 |
| 决策闸 | 过 AGENTS.md 第 7 条：先验证微调后在我们的 6 任务分类上准确率 ≥85% 再集成；微维护成本预估 >2h/月则降级为"实验性插件" |
| 数据冷启动 | 微调数据集可以来自 MVP 的用户选择日志（用户选的任务类型 = 天然标注），这是我们自己独有的数据资产 |

**给左力的一句话**：这是一个"方向正确、时点未到"的增强——先把规则式路由跑起来积累选择日志，日志就是未来微调 Laya 的燃料，届时集成是顺水推舟。
