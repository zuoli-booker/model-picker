# 大模型排名 + 路由应用 · 调整方案（决策版）

> 版本：v1.0 ｜ 日期：2026-09-28
> 说明：本文档是《大模型排名与路由应用-可行性评估报告》第八章「决策视角」的落地方案版。原则一句话：**单人副业最稀缺的资源是持续投入时间，一切围绕"用最小维护成本，最先验证最大的不确定性"。**

---

## 一、产品定位

### 1.1 一句话定位

> LiteLLM 解决了"**怎么接**"，OpenRouter 解决了"**替你接**"，本产品解决没人解决的"**接哪个 + 帮我配好**"。

### 1.2 两个核心组件

| 组件 | 形态 | 边界 |
|---|---|---|
| **策略生成器**（核心） | 开源工具 → Web 配置器 | 用户登记自己可调用的模型（API Key/URL/模型名，仅存本地），按任务类型 + 速度/质量/成本偏好，基于公开榜单数据生成透明、可解释的路由策略 |
| **可下载路由应用** | Docker 一键部署包 | 策略编译为 LiteLLM 配置，用户自有环境运行；BYOK 模式，平台不接触 Key、不经手请求 |
| ~~排名网站~~ | **降级为副产品** | 只接 2-3 个 API 数据源，自动生成模型详情/对比页（SEO 长尾），不做看板级打磨 |

### 1.3 模式边界（BYOK，法律风险切割）

- 用户自带 API Key，请求不经过平台服务器 → 不涉及 API 转售/代调、生成式 AI 备案、数据出境问题
- 平台定位 = **工具软件 + 信息聚合**，不是"API 中转站"
- 合规三要点：榜单引用标注来源并回链；底座只用 MIT/Apache-2.0（LiteLLM/One-API，**避开 AGPL 的 New API**）；页面挂免责声明

## 二、四处关键调整（相对原始方案）

| # | 调整 | 原方案 | 调整后 | 理由 |
|---|---|---|---|---|
| ① | **排名站降级：产品 → 副产品** | P0 花 3-5 周做精雕细琢的排名站 | 只接 OpenRouter + Artificial Analysis 等 2-3 个 API，自动生成页面 | 正面刚 DataLearner/AA 无胜算；排名站唯一不可替代的作用是供数据 + 引流，做到最低限度即可 |
| ② | **顺序反转：核心假设先验证** | P0 排名站 → P1 策略生成器 | 先做 2 周开源小工具验证 | 最大不确定性是"策略生成器有没有人用"，不是"排名站有没有人看"（已验证有） |
| ③ | **明确放弃，而非"远期可选"** | 学习式路由/用户体系/云端同步列为远期可选 | 第一年明确不做 | "远期可选"是范围蔓延温床；单人副业头号死因是维护负担过重导致烂尾 |
| ④ | **流量策略：GitHub 优先，SEO 后置** | 排名站 SEO 为主获客 | 开源社区（GitHub/V2EX/掘金/即刻）为主，SEO 慢养 | 目标用户是开发者，不在搜索引擎；开源工具自带传播属性，SEO 是 6-12 个月长线 |

**保留意见（诚实说明）**：调整①牺牲了排名站的产品竞争力，是有意识的赌注——赌开发者社区传播效率高于 SEO。若 V2 数据显示流量主要来自搜索，需回头补做排名站打磨。

## 三、路线图

### V0 · 开源验证（约 2 周）

**做什么**：开源小工具「模型选型 → LiteLLM 配置生成器」（CLI 或单页应用）

- 覆盖 20-30 个主流模型（用户真实会用的，含 DeepSeek/通义/Kimi/GLM 等国产模型）
- 5-6 种任务类型：写作 / 代码 / 客服 / 数据分析 / 翻译 / 长文本
- 评分公式透明可解释（向用户展示"为什么推荐这个模型"）
- 输出：LiteLLM YAML 配置文件
- 数据：手工整理 + OpenRouter API 即可，暂不建自动化管道

**验证什么**：核心假设——"策略生成"这件事有没有人要

**发布渠道**：GitHub + V2EX + 掘金 + 即刻

### V1 · 完整闭环（V0 验证通过后，约 4-6 周）

**做什么**：

- Web 策略配置器（模型清单登记 + 任务勾选 + 权重调节）
- 基础模型数据库（2-3 个 API 数据源，定时更新）
- 策略编译器：策略 JSON → LiteLLM 配置
- Docker 一键路由包（预装 LiteLLM，用户本地/自有服务器运行）
- 模型清单存 localStorage + 可导出 JSON（**不做账号系统**）

**验证什么**：完整闭环有没有人持续用

### V2 · 飞轮与留存（视 V1 数据决定）

- 排名页副产品：同一数据库自动生成 SEO 页面（长尾词："XX模型排名/对比"）
- **模型换代提醒**（最强留存钩子）：榜单发现比用户当前选择更强/更便宜的新模型时，邮件/微信推送"你的策略该更新了"
- 用量与成本看板（路由应用本地统计，可选匿名回传）

### 止损纪律

> V0 发布后 2-4 周内若无明显自然增长（Star 个位数、无人提 Issue/讨论），**果断停**。沉没成本只有 2 周，远比做 2 个月才发现没人要便宜。

## 四、做与不做（范围边界）

### ✅ 做

- 策略生成器（规则式：榜单数据 × 任务映射 × 用户权重）
- LiteLLM 配置编译 + Docker 打包
- 2-3 个数据源的定时聚合（官方 API 为主）
- 任务类型 → 榜单维度的映射规则（核心认知壁垒）
- 换代提醒（V2 起，复用数据管道）

### ❌ 不做（第一年明确放弃）

- 自建模型评测（只聚合公开榜单）
- 学习式语义路由（赛道已降温：Martian 转型、RouteLLM 停更、TensorZero 归档）
- 用户账号体系 / 云端策略同步
- 模型托管 / API 代调
- 任何形式的商业化
- 嵌入 AGPL 项目（New API）

## 五、技术栈（全部站在开源肩膀上）

| 层 | 选型 | 说明 |
|---|---|---|
| 路由底座 | **LiteLLM**（MIT，55k+★） | 100+ 厂商接入、fallback、成本追踪；策略编译为其 YAML 配置 |
| 数据源 | OpenRouter API + Artificial Analysis + OpenCompass 公开数据 | 标注来源并回链 |
| 前端 | 单页应用 / 静态站 + Chart.js | 可 fork ai-benchmark-arena 加速 |
| 数据存储 | SQLite（V0-V1） | 模型清单在用户侧 localStorage |
| 交付 | Docker 镜像 | 用户一键运行，BYOK |

## 六、成本估算

| 项目 | 金额 | 说明 |

| V0 验证 | **¥0**（2 周业余时间） | 开源工具，无服务器 |
| 服务器/域名 | ¥1,000-3,000/年 | V1 起；BYOK 模式无推理流量成本 |

| 数据维护 | 每月 1-2 天 | 长期主要成本 |
| **首年现金总投入** | **约 ¥1,500-5,000** | 真正投入是 2-4 个月业余时间 |

## 七、核心风险与对策

| 风险 | 对策 |
|---|---|
| 策略生成器没人用（最大不确定性） | V0 两周验证 + 止损纪律 |
| "选模型"低频，用户来了就走 | V2 换代提醒（订阅式选型顾问）+ 用量看板 |
| OpenRouter/DataLearner 上下夹击 | 死守"基于用户手头模型的透明策略 + 自托管"空白点 |
| 榜单可信度争议 | 每分数标注来源/方法/更新时间，做"按场景选榜"导航 |
| 范围蔓延 → 烂尾 | "不做清单"刚性执行；新功能先问：它增加多少每月维护时间？ |

---

## 八、如果只能做一件事

> **做策略生成器。**
> 它是"没人做过 × 你能做好 × 验证最便宜"的唯一交集。排名站是它的数据源，路由应用是它的交付物——都从它长出来，而不是反过来。
