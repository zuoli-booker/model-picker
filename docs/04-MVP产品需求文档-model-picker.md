## 1. 产品概述

### 1.1 一句话定义

一个开源命令行工具：回答几个问题（你有哪些模型、要干什么、看重什么），生成一份**可解释的大模型使用策略**和**可直接使用的 LiteLLM 配置文件**。

### 1.2 目标用户

「轻开发者」：用过 WorkBuddy/Trae/豆包等 AI 应用的非程序员上班族，手头有 2-5 家模型的 API Key，不知道该怎么搭配使用。

### 1.3 MVP 要验证什么（北极星）

**门1（第 2 周末）：GitHub ≥30 star 或有用户 issue 反馈。**
一切功能取舍以此为准：能帮助"让人看懂、想试用、愿意 star"的功能优先，其余一律砍。

### 1.4 竞争卡位

LiteLLM 解决"怎么接"，OpenRouter 解决"替你接"，本工具解决"**接哪个 + 帮我配好**"。差异化三件套：**非程序员视角、可解释推荐、直接可用的配置产出**。

## 3. 功能需求

### F1 交互问答流程（P0）

启动命令（名称即品牌，已定 `model-picker`）：

```bash
# 方式一：交互问答（主流程，US1）
python -m model_picker

# 方式二：预设场景快速生成（US6，P1，v0.2 再做）
python -m model_picker --preset weekly_report
```

**问答流程（4 步，每步支持回退修正）**：

```
第1步：你手头有哪些模型的 API？（多选，展示编号列表供勾选）
  ├─ 列表来源：内置 20 个模型清单（见 §5）
  ├─ 也支持手动输入清单外的模型名（标记"数据缺失，按通用策略处理"）
  └─ 至少选 1 个

第2步：你主要用 AI 干什么？（多选，任务类型枚举）
  ├─ 枚举（6 类）：写文案/写周报、翻译、看长文档/总结、写代码/改代码、
  │               数据整理/Excel、日常问答/查资料
  └─ 至少选 1 个

第3步：你更看重什么？（单选）
  ├─ A 省钱（成本优先）
  ├─ B 质量（效果优先）
  ├─ C 快（速度优先）
  └─ D 均衡（默认）

第4步：确认摘要 → 生成
  └─ 展示"你的选择"摘要，问"确认生成？（可回退修改某一步）"
```

### F2 推荐引擎（P0，核心逻辑）

**规则式，不是学习式**（硬约束：每条推荐必须可解释）。

1. **任务类型 → 能力维度权重表**（本项目的认知壁垒，初版如下，PM 维护）：

| 任务类型 | 写作能力 | 代码能力 | 长文本 | 推理能力 | 中文能力 | 速度 | 价格 |
|---|---|---|---|---|---|---|---|
| 写文案/周报 | **0.30** | — | 0.10 | 0.15 | **0.25** | 0.10 | 0.10 |
| 翻译 | 0.25 | — | 0.10 | 0.15 | **0.30** | 0.10 | 0.10 |
| 看长文档/总结 | 0.15 | — | **0.35** | 0.20 | 0.20 | 0.05 | 0.05 |
| 写代码/改代码 | — | **0.40** | 0.10 | **0.30** | 0.05 | 0.10 | 0.05 |
| 数据整理/Excel | 0.15 | 0.25 | 0.10 | **0.30** | 0.10 | 0.05 | 0.05 |
| 日常问答/查资料 | 0.20 | — | 0.05 | 0.20 | 0.20 | **0.20** | 0.15 |

2. **用户偏好调整**：第 3 步的选择将对应维度的权重 ×1.5（省钱→价格、质量→各能力维度、快→速度、均衡→不调整），然后归一化。
3. **打分**：每个入选模型按权重表加权求和，得出该任务下的得分排序。
4. **输出策略**：每个任务类型给出 **首选 + 备选**（首选=综合分最高；备选=同任务下"价格最低的够用选项"）。若用户模型清单中某任务无合适模型，明确说"你手头的模型里没有特别适合 X 的，建议考虑补充 Y"（Y 从全量清单推荐，标注"需要新开通 API"）。
5. **可解释性（US3 的实现）**：每条推荐附 2-3 句理由，格式固定——`推荐 <模型>：<它在该任务关键维度的表现> + <价格/速度事实>`。例：「推荐 deepseek-chat：中文写作维度得分 8.9（你的备选里最高），且百万 token 成本仅 ¥2，写周报绰绰有余。」

### F3 数据层（P0）

- 文件：`data/models.json`（MVP 手动维护，不做 API 拉取——阶段2 才建管道）
- 规模：**20 个模型**（国内 13 + 国际 7，清单见 §5）
- 字段结构：

```json
{
  "id": "deepseek-chat",
  "display_name": "DeepSeek V4",
  "vendor": "深度求索",
  "origin": "cn",
  "pricing": { "input_mtok_cny": 2.0, "output_mtok_cny": 8.0 },
  "speed": { "tokens_per_sec": 60 },
  "context_window_k": 128,
  "scores": {
    "writing": 8.9, "coding": 8.2, "long_context": 7.5,
    "reasoning": 8.7, "chinese": 9.2
  },
  "scores_source": "OpenCompass 2026-09 / Artificial Analysis 2026-09（整理时标注实际来源与日期）",
  "notes": "性价比标杆，中文强"
}
```

- **数据整理规范**：分数 0-10 分制；同一维度尽量同源（跨源需标注）；数据文件头部写 `updated_at` 和各来源日期；分数允许主观校准但需在 notes 说明。**PM（阿腾）负责数据整理交付，开发（Trae）先用占位数据开发，不必等数据。**

### F4 输出物（P0/P1）

1. **终端报告**（P0）：按任务分组展示策略表 + 每条推荐的理由
2. **LiteLLM 配置文件**（P0，US4）：生成 `model-picker-config.yaml` 到当前目录，格式：

```yaml
model_list:
  - model_name: writing          # 任务别名，用户的应用统一调别名
    litellm_params:
      model: deepseek/deepseek-chat
  - model_name: coding
    litellm_params:
      model: deepseek/deepseek-coder
router_settings:
  routing_strategies: ...        # 按任务别名路由
```

3. **Markdown 策略说明**（P1）：`my-strategy.md`，人话版策略报告（含成本估算表 US5），可直接分享——这也是内容运营的素材模板（小红书笔记"我的多模型配置"的具象化）。
4. **成本估算**（P1，US5）：按"轻度/中度/重度"三档假设用量（写死假设，注明），估算月成本对比"全用最贵模型"的节省额。

## 4. 非功能需求

| 项 | 要求 |
|---|---|
| 运行环境 | Python 3.10+；依赖**最多 3 个**第三方包（力争 0 依赖纯标准库；yaml 生成可用字符串模板避开 PyYAML） |
| 语言 | 交互与输出全中文；代码注释中文 |
| 开源协议 | MIT |
| 安装方式 | `git clone` + `python -m model_picker`（MVP 不上 PyPI，README 写清楚） |
| 平台 | macOS / Windows 双平台可跑（路径处理用 pathlib，不用硬编码斜杠） |
| 无网络运行 | MVP 完全离线（数据内置），不调任何外部 API |

## 5. 首批模型清单（数据整理基线，共 20 个）

**国内 13**（示例，实际以整理当日各家在售型号为准）：DeepSeek ×2（标准/推理）、智谱 GLM ×2、通义 Qwen ×2、Kimi ×1、豆包 ×1、混元 ×1、文心 ×1、阶跃/Mistral 中国区等视整理时情况补足
**国际 7**：OpenAI GPT ×2、Anthropic Claude ×2、Google Gemini ×2、xAI Grok ×1

> 国际模型保留原因：部分轻开发者有海外 Key 或通过聚合平台使用；价格按官方牌价折算人民币并标注汇率日期。

## 6. 明确不做（MVP 边界）

- ❌ Web 界面（阶段2）
- ❌ 自动拉取榜单 API（阶段2 建管道，MVP 手动 JSON）
- ❌ 真实调用模型测试速度（数据用公开测评数字）
- ❌ 学习式/语义路由
- ❌ API 托管、用户系统、云同步
- ❌ 上 PyPI

## 7. 验收标准

1. US1-US4 全部可演示通过（一个完全不会命令行的用户，10 分钟内走完问答并拿到可用配置）
2. 生成的 yaml 能被 LiteLLM 正常加载（用 `litellm --config model-picker-config.yaml` 验证）
3. 每条推荐都有理由，无黑盒
4. Windows/macOS 各跑通一遍
5. README（中文）包含：30 秒能看懂的演示 GIF/录屏、安装三步、示例输出——README 质量直接决定 star 转化

## 8. 建议实施顺序（给 Trae）

1. 数据结构 + 占位数据（`models.json` 20 个占位模型）→ 2. 问答流程（F1）→ 3. 推荐引擎（F2）→ 4. 终端报告 → 5. yaml 生成（F4-2）→ 6. README → 7. P1 项（成本估算 / md 报告 / preset）按余量做
> 每完成一块独立 commit；开发走特性分支（Qoder 已确立分支约定），完成后合回 main 由左力验收。
